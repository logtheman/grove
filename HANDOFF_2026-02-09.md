## How It Works

### Command Execution Flow

1. **Frontend** calls `scanForWorkspaces(cwd, terminalId)` or `getRemoteGitStatus(workspaceId, terminalId)`

2. **Backend** `execute_in_terminal()`:
   - Generates UUID for this execution
   - Wraps command: `echo 'GROVE_EXEC_START_<uuid>' && <command> && echo 'GROVE_EXEC_END_<uuid>'`
   - Writes to terminal PTY

3. **PTY Reader Thread**:
   - Detects `GROVE_EXEC_START_<uuid>` → creates `CommandExecution` entry
   - Accumulates all output between markers
   - Detects `GROVE_EXEC_END_<uuid>` → marks complete
   - Filters command lines from terminal display

4. **Backend** `execute_in_terminal()`:
   - Polls `pending_commands` for completion (10s timeout)
   - Returns captured output
   - Cleans up completed command

5. **Backend** parsing functions:
   - Strip command echoes and ANSI codes
   - Parse structured output (worktree list or git status)
   - Return workspaces or git status to frontend

### Remote vs Local Detection

**Frontend logic** (`src/components/dashboard/DashboardPanel.tsx:30-44`):
```typescript
const isLikelyRemote = path.startsWith("/") && !path.startsWith("/Users/");
```

- Remote paths: `/home/logan/...`, `/root/...`
- Local paths: `/Users/loganmurdock/...`

When remote workspace selected:
- Auto-fetch git status if none exists
- Show refresh button
- Use `getRemoteGitStatus()` instead of `getGitStatus()`

## Architecture Notes

### Why Terminal Execution for Remote?

**Problem**: Rust can't directly access remote filesystem - paths like `/home/bento/carrot/customers/ursa` don't exist locally.

**Solution**: Execute git commands in the active terminal session (which is SSH'd to Bento), capture output, parse it locally.

**Benefits**:
- Works with any remote connection (SSH, tmux, etc.)
- No special remote access code needed
- Reuses existing terminal infrastructure

### Command Execution Design

**Marker-based capture** (vs other approaches):
- **Why not `script` command?** Not universally available, complex cleanup
- **Why not expect-style?** Hard to parse arbitrary output reliably
- **Why markers?** Simple, reliable, easy to filter from display

**Challenges solved**:
- Terminal echo (commands appear in output) → Filter lines starting with `git ` and containing `2>/dev/null`
- ANSI escape codes → Strip before parsing
- Command cleanup → Remove from `pending_commands` after reading
- Timeout handling → 10s with cleanup on timeout
- Display blocking → Only hide specific patterns, not all output

**Before Grove**:
- Manually cd to each worktree
- Run `git worktree list` to remember what exists
